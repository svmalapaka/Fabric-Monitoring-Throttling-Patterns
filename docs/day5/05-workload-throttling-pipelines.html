Pipeline Throttling

Pipelines in Microsoft Fabric can be throttled when too many activities run at once or when their combined resource usage exceeds capacity limits. Throttling may manifest as delayed starts, slower execution, or queued runs.

Typical pipeline throttling behaviors:

  • Runs waiting in a queue before execution
  • Longer overall pipeline duration under heavy load
  • Limited parallelism enforced by the platform

To reduce pipeline throttling:

  • Stagger heavy jobs instead of running them all at once
  • Optimize data movement and transformations
  • Monitor CU usage during peak pipeline windows
